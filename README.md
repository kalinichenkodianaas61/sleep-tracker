# Sleep tracker

Console sleep tracking program

Name: Sleep tracker
For whom: for me to see how much and how I sleep
Record: date, falling asleep time, wake up time, sleep quality (1-100%)
Operations: show all, find by quality/duration, delete
Reports: average duration/quality of sleep, shortest/longest sleep

# Запуск сервера

Команди запускати з теки проєкту, у двох окремих терміналах:

Спочатку API:
   py -m waitress --listen=127.0.0.1:8000 app:app
Потім тунель:
   cloudflared tunnel --url http://127.0.0.1:8000

Адреса тунелю з'являється в рамці на початку виводу cloudflared.


# Безпека

Сервіс працює на моєму ноутбуці й виставлений в інтернет через тунель Cloudflare (cloudflared). Вхідних портів і окремого Linux-сервера немає, тому VPN, nginx, ufw і fail2ban з методички тут не застосовні. Їхню роль виконують локальний доступ до адмінки і вихідний тунель.

## Секрети

Токен адміністратора лежить у файлі `.env` (змінна `ADMIN_TOKEN`), якого немає в git: він у `.gitignore`. Код читає його через `python-dotenv` (`os.environ`). Перевірка: `git log --all --oneline -- .env` нічого не виводить.

## Адміністративні маршрути

Видалення і експорт винесені під `/admin/`: `DELETE /admin/records/<id>`, `GET /admin/export`. Захист двома шарами:

1. Токен у заголовку `X-Admin-Token` (порівняння через `hmac.compare_digest`; якщо токен не заданий, доступ закритий).
2. Запити, що прийшли через тунель (мають заголовок `Cf-Connecting-Ip`), відхиляються з 403. Адмінка доступна лише з самого ноутбука (`127.0.0.1`). Це замінює VPN.

Приклад виклику локально: `curl.exe -X DELETE -H "X-Admin-Token: ..." http://127.0.0.1:8000/admin/records/5`.


## Резервні копії

`backup.py` робить копію `data.db` через `sqlite3.backup` у папку `backups/` (файл `data-РРРР-ММ-ДД.db`). Запускається щодня Планувальником завдань Windows. Відновлення перевіряється підміною `data.db` копією з `backups/`.

## Аудит

| Загроза | Як перевірити | Статус |

| SQL-ін'єкція | POST `/records` з `date = '; DROP TABLE records; --`, потім GET `/records` | Закрито: усі запити в `storage.py` з параметрами `?`; формат дати, часу і якості перевіряється до запису (відповідь 400) |
| XSS у фронтенді | додати запис зі значенням `<img src=x onerror=alert(1)>` | Закрито: у `frontend/index.html` дані виводяться через `textContent`, а не `innerHTML`; поля також обмежені форматом |
| Зайвий вхід на сервер (ssh) | спроба підключитися по ssh до ноутбука | Не застосовно: ssh-сервер не запущено, сервер для входу відсутній |
| Обхід Cloudflare | звернення до сервісу в обхід домену | Закрито: API слухає лише `127.0.0.1:8000`, вхідних портів немає, зовнішній трафік іде тільки через тунель |
| Флуд запитами | 100 POST у циклі | Відкрито: rate limiting у Cloudflare не налаштований; прийнятно для навчального сервісу з малим навантаженням, закривається правилом Rate limiting у Cloudflare |
| Видалення даних сторонніми | `DELETE /admin/records/1` без токена і через тунель | Закрито: токен + відхилення запитів через тунель (403) |
| Секрети в git | `git log --all --oneline -- .env` | Закрито: `.env` у `.gitignore`, в історії його ніколи не було |
| Втрата даних | видалити `data.db`, відновити з копії | Закрито частково: щоденна копія через Планувальник; копії лежать на тому ж ноутбуці, тож при втраті диска зникнуть разом з базою, що прийнятно для навчальної роботи |
| Відкриті порти | `netstat -an` | Закрито: чути лише `127.0.0.1:8000`, тунель працює через вихідне з'єднання |
| Застарілі пакети | `py -m pip list --outdated` | Відкрито: версії зафіксовані в `requirements.txt`, оновлюються вручну разом з Windows Update |
| Режим налагодження Flask | запуск через `app.run()` | Закрито: `debug=True` прибрано; сервіс запускається через waitress |

# Класи, дві таблиці, журнал, тести

- `models.py`: клас `SleepRecord` (дата, час сну і пробудження, якість 1-100, фактор дня). Усередині програми ходять об'єкти, словники лишаються лише на межі з JSON і базою (`to_dict`, `from_row`).
- База: таблиця `factors` (фактори дня: кава, спорт, стрес...) пов'язана з `records` через `factor_id` (`PRAGMA foreign_keys = ON` у `storage.connect()`). Звіт через JOIN: `GET /report/factors` (кількість ночей і середня якість по факторах).
- Журнал дій: таблиця `audit_log`, кожне додавання і видалення записується з часом. Перегляд: `GET /admin/log?limit=50` (лише локально і з токеном).
- `migrate.py`: одноразове перенесення старої бази (лабораторна 10) у новий формат. Перед запуском сам робить копію в `backups/`. Запуск: `py migrate.py`.
- Тести: `py -m pytest -v` з кореня проєкту (`tests/test_logic.py`, `tests/test_storage.py`, `tests/test_app.py`). Тести маршрутів працюють на окремій тимчасовій базі через змінну `DB_PATH`.
